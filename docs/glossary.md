# Glossary

Canonical term definitions for Goodboy. Use these in code, UI, docs, and issues.

| Term                             | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **workspace**                    | A registered project directory. Sessions are scoped to a workspace. Three kinds exist (`WorkspaceKind`): **repo**, one project folder whose sessions each get their own git worktree; **composite**, a container linking two or more repo workspaces so one session can span all of them; **simple**, a standalone folder for non-developer work whose sessions are plain directories with no git at all. The `kind` column defaults to `repo`.                                                                                                                                                                                                                                                                  |
| **workspace git state**          | Derived on demand from the workspace root by the `workspace_git_status` command, never stored: `missing` (folder unreachable), `absent` (no repository at the root), `unborn` (repository with no commit yet), `ready` (repository with at least one commit, carrying branch, ahead, behind and dirty counts). A `repo` workspace can sit at `absent` or `unborn`: it was registered on a plain folder, the Overview shows the `git init` commands for the user to run, and session creation stays unavailable until `ready`. Goodboy never runs git init, never commits, never adds a remote on the user's behalf.                                                                                              |
| **session**                      | A goal-oriented container inside a workspace. Owns the git worktree, the branch, the shared context slots, the budget, and the list of agents. Auto-spawns one default agent on creation. Has a user-selectable status (wip / waiting / blocked / done). Supports soft-delete and archive. _DB table:_ `sessions`.                                                                                                                                                                                                                                                                                                                                                                                               |
| **agent**                        | An independent chat thread inside a session. Has its own provider/model/effort/verbosity, its own message history, its own kind label, and its own status (pending / running / completed / failed). User spawns agents at will from the agents lens; rename inline via the pencil icon. Supports soft-delete. _DB table:_ `agents`.                                                                                                                                                                                                                                                                                                                                                                              |
| **agent kind**                   | One of 10 role labels: planner, scout, implementer, debugger, tester, reviewer, pr-reviewer, docs, resolver, generic (displayed as "Generalist", badge `GEN`). Carries an optional system prompt and maps to an agent role (`KIND_TO_ROLE`); that role's provider, model, and effort come from `ROLE_DEFAULTS` unless the workspace overrides the role in Provider Studio. With no override, scout, docs, and generic drop to the provider's cheap model at low effort. Inferred from agent name or first user turn, or picked in the create-agent popover (which hides resolver: only the resolve UI spawns it).                                                                                                |
| **shared context**               | The synthetic slots (goal, files touched, decisions, open questions, last summary) attached to a session. Visible in the right-side context panel; auto-populated by the summarizer after every agent turn. All agents in the session read the same context. Slots are collapsible, rendered as markdown, and have history tracking.                                                                                                                                                                                                                                                                                                                                                                             |
| **plan**                         | A first-class artifact captured from a planner agent's output via `<<plan>>...<<plan>>` markers. Session-scoped. Status: active / consumed / superseded. Other agents consume plans; consumption is tracked. Viewable in the plans modal with tree rendering. _DB table:_ `session_plans`.                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **plan consumption**             | A record that an agent consumed (read and acted on) a specific plan. Tracked per agent per plan with timestamp. _DB table:_ `plan_consumptions`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **session status**               | User-selectable lifecycle label on a session: wip, waiting, blocked, done. Displayed as an icon in the sidebar session row. Persisted to DB.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **workflow** _(beta)_            | A workspace-scoped template of ordered steps (e.g. scout, planner, implementer, reviewer). Comes from the seeded library, settings authoring, or the planner agent ("design custom" chip). Attaching it to a session pre-spawns one pending agent per step; the same workflow can attach more than once, each attach being its own run. After spawn the agents are independent and live alongside any free-form ones. _DB tables:_ `workflows` + `steps`. See [workflows.md](workflows.md).                                                                                                                                                                                                                      |
| **workflow run**                 | One attach of a workflow to a session, keyed by `workflow_run_id`. Owns the current step ordinal, the auto-run and trigger-mode flags, and the run's plan and open questions, so two runs of the same workflow on one session do not read each other's state. _DB table:_ `session_workflows`.                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **step**                         | One agent role inside a workflow. Carries a name, a prompt prefix, optional provider/model overrides, and an expected output (migration 77) that the step-output summarizer is told to extract first, so the handoff to the next step leads with it. Becomes the seed for one pre-spawned agent.                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **planner**                      | A cheap-tier provider call that turns a free-text theme into a `PlannerOutput` (workflow name + ordered steps). Surfaced as the "design custom" chip in the session overview (after session creation).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **worktree**                     | The git worktree directory for a session: the path on disk where files live while the session is active. Removed when the session ends; the branch is preserved.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **branch**                       | The git branch the worktree checks out. Named `<prefix>/<slug>` by default. Preserved after the session ends for manual review or merge.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **skill**                        | A markdown + scripts automation invocable from chat via `/skill-name`. Discovered from `<workspace>/.kay/skills/*.md` or `<workspace>/.claude/skills/<name>/SKILL.md`; auto-rescanned on workspace add. Per-workspace, not global.                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **permission rule** _(beta)_     | A tool matcher plus a decision (allow / deny / ask) at global, workspace, or session scope. Nothing intercepts a call: allow and deny rules compile into `--allowedTools` / `--disallowedTools` when the turn spawns (Claude only), `ask` rules compile to nothing. Headless `claude -p` never prompts and never waits, it reports the calls it refused in `result.permission_denials[]`; the envelope parser turns each one into a `permission_request` event and the reducer parks the turn in `blocked`. Approving at session scope or wider writes a rule, and the explicit retry re-sends the turn so the agent can call the tool again. A `once` approval is never persisted, so a retry cannot honour it. |
| **turn**                         | One user prompt → one assistant response, including all streaming events in between. The atomic unit of interaction within an agent.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **parallel group** _(unshipped)_ | Multiple agents executing in parallel on throwaway worktrees, merged back at completion. The runtime gate is enabled (`AGENT_FEATURES.parallelAgents`), but no authoring surface writes `steps.parallel_group`, so routing never reaches it yet. See [workflows.md](workflows.md) for what is actually wired.                                                                                                                                                                                                                                                                                                                                                                                                    |
| **notification**                 | A persistent feed entry (info / warning / error) for budget alerts, session events, and system messages. Viewable in the notification center (bell icon in sidebar top). Supports toasts for transient display. _DB table:_ `notifications`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **diff comment**                 | A user annotation on a specific file + line in the diff viewer. Can be open, resolved, consumed (by a reviewer agent), or deleted. _DB table:_ `diff_comments`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **resolver**                     | An agent spawned to address one review or diff comment with a local commit, never a push. Where it came from is recorded in `agents.source_kind` (`review_comment`, `issue_comment`, `diff_comment`); migration 76 backfills older rows from the stored thread id or comment url and leaves the rest empty, so the UI infers the origin for those. Resolvers run one at a time on the session worktree, in `ordinal` order. A stuck one can be force-closed: the turn is cancelled, the agent is stamped `skipped`, and the next queued resolver starts. The queue and the per-resolver state are in memory only, so an app restart loses them and queued resolvers no longer start on their own.                |
| **initialization (db wipe)**     | Settings → Initialization → "Wipe local database". Drops every workspace / session / agent / message in `~/.goodboy/data.db` and re-runs migrations on next boot. API keys in the OS keychain are not touched.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Overview**                     | The board surface shown when a workspace is active but no session is selected. Renders the stage board only; the left sidebar is hidden. Entry point in the breadcrumb trail.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Step** (breadcrumb term)       | Requester shorthand for a session, used in breadcrumb trail descriptions. The rendered crumb label is the session's goal field (falling back to "untitled session"), not the literal word "step".                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **breadcrumb chrome**            | The `BreadcrumbChrome` wrapper applied to the breadcrumb row rendered by `AppBreadcrumb`. Currently used inside `WorkspaceLinkDialog` (workspace-create dialog). Carries one of five states: `none`, `workspace-launcher`, `workspace-create`, `pull-request`, `resolve`. Determines visual treatment of the breadcrumb depending on which surface is active.                                                                                                                                                                                                                                                                                                                                                    |
| **leftHidden**                   | Additive `AppShell` prop. When `true`, the left sidebar column animates to zero width and the resize handle is suppressed. Set by `App.tsx` as `!currentSession`: sidebar is hidden at Overview and revealed when a session is entered.                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

# Overview and activity

Open a session to see what it is for, what needs you and what happened so far.

### Session overview

The Overview is titled with the session's name, its linked issue key in gray before it, and a single click renames it in place across the whole title row (Enter saves, Escape cancels). A small ring at the end of the field fills toward the 120 character limit and turns amber near it. It reads top to bottom: the goal, then anything a branch needs you to decide (a closed worktree with **Reopen**, a failed action with **Retry**, a stopped rebase, a branch that moved), then **Needs you**, **Next** and **Activity**. **New** in the header starts an agent, a workflow or a write-up. The projects, branches and linked work of the session sit in the sidebar: click a branch to open its pull request, comments, files, commits and checks.

### Refresh a session

Pull requests opened outside Goodboy, by an agent or from a terminal, show up when a turn ends or when you come back to the window. **Refresh** in the session's `...` menu, or **⌘⇧R**, re-reads projects, branches and pull requests right away.

### Activity

Follow what happened in a session in two views. **Activity** has one row per agent, workflow run or fix run, with its state, model, time and cost; step numbers line up in one column that no lane crosses. Every row carries the glyph its concept has in the sidebar and the **New** menu: a workflow run the Workflows glyph, an orchestrated run the orchestrator glyph, an agent its role. The **Needs you** block above Next lists what waits on you, and each row opens the exact ask. **Log** lists the plain facts, such as context changes, branch events and links, newest first with a search box.

### New session overview (experimental)

Try another way to read a session. Every session header has a two-state toggle left of **New** (left of **Restore** on an archived session), the same height as **New**: **Classic** and **New**, the current one selected, with "New overview (Experimental)" in the tooltip of **New**. It is the `SegmentedTabs` primitive, no popover. Classic is the default; the choice is the same for every window of the app. **New (Experimental)** turns the Activity part of the Overview into three parts: **Now** says where the session stands, **Next** is one stack of cards, and **What was done** lists finished work by day, with **Full log** opening the log in a drawer. Selecting **New** shows no message. Selecting **Classic** while on the new one goes back at once and says "Back on the classic overview." with **Undo**. ⌘K has **Use the new session overview** and **Use the classic session overview**. Another window picks the change up the next time it gets focus. If the setting cannot be saved, the old overview stays and the error is shown. A **What was done** row is titled with the first sentence or first step of what the agent said (an orchestrator recap shows its first done line, never raw JSON) and opens to the full text, and a finished session with a pull request in **Now** reads like "Checks passed on #309. Ready for review.", from the pull request and its checks.

The **Now** header holds the state word with its dot and, when rows in the **Decide** or **Fix** group of **Next** wait on you, one count on the right, as in **6 wait on you** (`needsYouCountOf`, the same rows Next draws; Update and Ship never count); pressing it scrolls to **Next**. That count is the only place Now says how many things wait: the sentence names at most the first two agents or runs, in the order of the list, and never counts. Agents and runs are listed by when they started, so a row keeps its place when its state changes (`liveGroupsOf`); the state shows in its word. When an agent Auto started is stuck, Now says **Stuck** in its header and on the Auto row, names the agent and why in the sentence (`Auto is stuck: "<name>" is blocked.`), and puts one line under it: **Retry**, which runs the same retry as the Next card and keeps the line with the error when it fails, **Answer**, which opens the Auto chat, and **Stop** (`StuckActions`).

In the new overview, **Now** tells the story of every branch of the session, one row each under **Branches**. A row names the branch, shows one connected track of six stages (Commit, Push, Pull request, Checks, Review, Merge), filled up to where the branch stands with the state color only on that stage, the step the branch stands at (for example **Checks failing** in red, **No pull request** in grey, **Approved** in green or **Merged** in violet, the same color the state has everywhere in the app), and one short fact about it, such as "2 threads to answer" or "24 commits to push". The columns line up from row to row, and the project shows only when the branches come from two or more projects. A step that does not apply to a branch (a repo with no checks, a pull request that needs no review) is a short dash instead of a circle, a queued pull request shows **In merge queue** on the last step, and every stage names itself on hover. Branches that need you come first, merged ones last. With many branches the list shows eight and one line counts the rest. The rows hold no button: the verbs stay in **Next**, and a right click on a row opens the same branch menu as the rail (`useMountMenuTarget`). See [mounts.md](../mounts.md) for how each word is read.

### Next

Know the moves that unblock the task, such as answering a question, fixing a failing check or opening a pull request. **Next** offers up to three, each as one short button such as **Start**, **Analyze** or **Push**, the first one filled, and **Not now** puts a suggestion away until the situation changes. Next only gives the hint that starts something: once **Analyze** starts the Debugger on a failing check, its next moves (open the analysis, **Start fix**, **Push**) sit on that run's Activity row, and a workflow's ready step keeps its **Start** on the run row. Next does not repeat them. **Open a pull request** names the branch it opens in its title, as in **Open a pull request for hl/refund-retry**, with the project and the commits ahead under it. With several branches still without a pull request, Next shows one card for the branch furthest ahead, **⋯** lists every one of them, and **Not now** moves the card to the next branch. Once a pull request merges, Next offers **Remove the payments-api worktree** with the reason and its size (`#418 merged · 412 MB`), or one row for several merged worktrees. When the button starts an agent, the icon on the left is that agent's role in its color, and the button carries the same icon. Other ways to do it, such as starting a tester instead, sit in the **⋯** menu, where pointing at one shows its role on the icon. **Not now** says Dismissed with **Undo**, and ⌘Z brings the last dismissed suggestion back, several times in reverse order.

In the new overview, **Next** groups its rows by what you do, always in this order: **Decide** (a plan waits on your OK, a question), **Fix** (a stuck agent, a failing check, review conversations), **Update** (branches behind or diverged) and **Ship** (push, open a pull request, mark ready, merge, clean up). An empty group is not drawn. Each group folds behind its name with its row count and, while folded, the branches or plans it holds; the first group with rows opens, and what you open or fold stays as you left it for that session (`nextGroupsOf`, `NextGroup`, the `next-view` store slice). Inside a group a row keeps the place it had when it first showed in this window, so a refresh never moves a row and a new one lands at the end. One button is filled, on the first row of the first open group. The **Next** header counts every row.

An item is in **Next** only while you are the next one to act. An agent Auto started that you stopped or declined leaves Next and shows in **What was done** as "You stopped the reviewer" with **Retry** in its detail; one a later agent replaced on the same branch leaves too. A stopped rebase of a branch that is still behind is not a card of its own: the "branches behind" card says how many rebases stopped and lists each one in its **⋯** menu.

Each branch, pull request or Auto plan shows once per kind of work. When an agent Auto started is stuck on a branch that also has a failing check, or two of its agents are stuck there, Next shows one row led by the worst blocker (blocked, then timed out, then never started, then a check), says "and 1 more" in its sentence and puts the others in its **⋯** menu. A stuck agent reads by its role and state, as in "The tester timed out. It ran out of time.", never the quoted request Auto sent it. A row's title is its subject: a plan that waits on your OK is titled by the plan's name, with the sentence "Plan v3 waits on your OK. The run covers 4 branches." (the branches its agents work on; `planSentenceOf`), and a **Fix** row on a known branch is titled by the branch and its open pull request, as in "hl/feat-center-home-page · #9995", with one sentence under it such as "4 review conversations wait for a fix." (`nextRowCopyOf`, `useBranchNames`). Rows in **Update** and **Ship** keep their verb titles, except a stopped rebase: it is titled by its branch, says in one sentence what stopped ("2 files conflict with main: MembersPage.tsx and 1 more. Your branch is as it was.", from `rebaseStopRowOf`) and leads with the verb that fixes it, **Resolve with Auto**, **Bring them in**, **Retry rebase** or **Fix with agent**, with **Resolve myself**, **Keep branch as it was**, **Undo rebase** and **Open branch** in its **⋯** menu as they apply; a click on its title opens the branch with the rebase panel. A diverged card of the same branch folds into that row and its verb into the **⋯** menu, never as "and 1 more" (`foldDivergedIntoStops` in `actionCardsOf`). When every open question out of view was asked by one Auto run (its root or an agent it started), **Answer open questions** is not a row of its own: it folds into that run's Decide row as "and 2 questions", and **Answer** sits in the row's **⋯** menu (`askingAutoRootOf`, the `rootAgentId` of the answer-questions suggestion). Questions from two runs, or from an agent outside Auto, keep their own row.

A group can act on its rows at once from its header (`nextBulkOf`). **Fix** with two or more stuck agents Auto can retry shows **Retry 3**, counting the stuck agents folded into a branch row too: it runs each agent's own **Retry**, so each one reports its own result, a row whose retry fails stays with its error and a second **Retry 3** runs again. **Update** with two or more branches behind or stopped shows **Update all 4** (`updateAll`): one click rebases every behind branch and every stopped one with git, one at a time, and brings origin in on each branch where someone pushed, each with its own lease. It never hands a conflict to Auto and never starts the History rewriter: a branch that stops on a conflict stays as its own row with **Resolve with Auto**, and a branch that fails keeps its row with the error, so its own verb retries it. A second click while it runs does nothing. The rebase picker with **Also tidy commits with Auto** stays on the rebase card itself. A click on a row's title opens its place: a stuck agent or a plan opens the Auto step, a check, review conversations or a pull request opens that tab of the branch, questions open the questions lens and an owner card opens its row (`openFor` in `useActionCardActions`, `suggestionPlaceOf`). A card that spans several branches, like the rebase card, opens nothing.

### Time left

See how long a step has left, estimated from your own past runs. Queued steps show a range, and a run slower than usual turns its time warm. Resting on the time opens a card with the time running, the usual range, the cost and the basis (`workTimeCardOf`).

### Changes

See and undo what agents changed in a session without a branch. In a plain folder agents edit in place, and every writing turn saves what it may change first, shell commands such as `rm` and `mv` and new files included. **Changes** in the session rail lists each turn, newest first, with the files it added, changed or removed and their line counts; pick a file to see its text before and after, with the changed words marked. **Restore to before turn 3** puts one file back, **Restore turn 3** puts back the whole turn, and **Remove this new file** takes out a file the agent created. Each restore first saves the text you have now, so **Undo restore** puts it back, and a restore over text that changed after the turn asks in place before it writes. The rail's **Folder** group names the folder and what agents do there, the Overview opens on a card that says where agents write and what is saved, and each writing turn in the chat ends in a card with **Review changes** and **Restore turn**. Versions are kept until 30 days after the session ends, within a cap per folder of 1 GB or the folder's own size, whichever is larger; the page shows how much they use, what was left out (files over 15 MB, links that leave the folder, dependencies and build output), and Storage shows their size under **Saved versions**. A session that still works in an older session folder keeps its list of file versions under the same page.

# Overview and activity

Open a session to see what it is for, what needs you and what happened so far.

### Session overview

The Overview is titled with the session's name, its linked issue key in gray before it, and a single click renames it in place across the whole title row (Enter saves, Escape cancels). A small ring at the end of the field fills toward the 120 character limit and turns amber near it. It reads top to bottom: the goal, then anything a branch needs you to decide (a closed worktree with **Reopen**, a failed action with **Retry**, a stopped rebase, a branch that moved), then one card per job in the order of who acts: **Needs you** (you must), **Running** (agents are), **Next** (you may), **Branches** (where each branch stands) and **Done** (finished). An empty card is not drawn, and an archived session keeps only **Done** (`overviewCardsOf`). There is one Overview: a choice of Classic stored by an older version reads as these cards. **New** in the header starts an agent, a workflow or a write-up. The projects, branches and linked work of the session sit in the sidebar: click a branch to open its pull request, comments, files, commits and checks.

### Refresh a session

Pull requests opened outside Goodboy, by an agent or from a terminal, show up when a turn ends or when you come back to the window. **Refresh** in the session's `...` menu, or **⌘⇧R**, re-reads projects, branches and pull requests right away.

### Full log

Follow what happened in a session in one list. **Full log** on the **Done** card, or **Open the full log** in the session's **⋯** menu and ⌘K, opens the log in a drawer beside the page: one row per agent, workflow run or fix run, with its state, model, time and cost, and the plain facts, such as context changes, branch events and links, newest first with a search box. Step numbers line up in one column that no lane crosses. Every row carries the glyph its concept has in the sidebar and the **New** menu: a workflow run the Workflows glyph, an orchestrated run the orchestrator glyph, an agent its role. **Mark all seen** clears the unread marks. The Activity and Log tabs of earlier versions are this one list now.

### Cards

**Needs you** holds the **Decide** and **Fix** rows of Next (a plan that waits on your OK, a question, a stuck agent, a failing check, review conversations) and counts them in its header; every group is open. **Running** lists the agents and runs at work, stuck first, then what waits on you, then what decides, then what works, each in the order it started (`liveGroupsOf`). Every row starts with its kind (**Workflow**, the role of an agent, **Auto agent**), then the title, the branch it writes to in one **Where** column (blank when it writes nowhere, with the project only across two projects, hidden in a column under 640px), its state or the run's own next move, and its time. A run shows its steps as a bar: done steps grey, the running step in the color of its role and a step that waits for your go amber; resting on the bar shows the step, the workflow, the role, the model, the time in and what comes next, and a click opens the step. The run's next move is the run page's own button (**Start step 2**, **Review plan**, **Answer**); **Answer** opens the question in the side drawer and the page stays. That move is not repeated in **Needs you**. The agents a run, an agent or Auto started hang under it on one thin line. **Next** holds **Update** and **Ship**; its groups fold until nothing needs you, and only one button is filled across both cards, on the first row of **Needs you** or, with nothing there, the first row of **Next**. **Branches** lists the branches still in play. **Done** says in one line which branches merged or closed and how many runs and agents finished, with **Full log** beside it (`doneSummaryOf`).

**Branches** tells the story of every branch of the session, one row each. A row names the branch, shows one connected track of six stages (Commit, Push, Pull request, Checks, Review, Merge), filled up to where the branch stands with the state color only on that stage, the step the branch stands at (for example **Checks failing** in red, **No pull request** in grey, **Approved** in green or **Merged** in violet, the same color the state has everywhere in the app), and one short fact about it, such as "2 threads to answer" or "24 commits to push". The columns line up from row to row, and the project shows only when the branches come from two or more projects. A step that does not apply to a branch (a repo with no checks, a pull request that needs no review) is a short dash instead of a circle, a queued pull request shows **In merge queue** on the last step, and every stage names itself on hover. Rows go by whose move it is (`RANK_OF_STATE` in `branchStoryOf`): blocked first (checks failing, conflicts, changes requested, remote branch gone), then ready to merge, then your move (not pushed, no pull request, draft, nothing committed), then a branch an agent works on, then waiting on others (in review, checks running, in merge queue). Two branches of one rank keep the order they were first seen, and a Next card never moves a row. A merged or closed branch leaves the list for the **Done** line. With many branches the list shows eight and one line counts the rest. The rows hold no button: the verbs stay in **Next**, and a right click on a row opens the same branch menu as the rail (`useMountMenuTarget`). See [mounts.md](../mounts.md) for how each word is read.

When an agent Auto started is stuck, the Auto row says **Stuck** and one line under it offers **Retry**, which runs the same retry as the Fix row and keeps the line with the error when it fails, **Answer**, which opens the Auto chat, and **Stop** (`StuckActions`).

### Next

Know the moves that unblock the task, such as answering a question, fixing a failing check or opening a pull request. **Next** offers up to three, each as one short button such as **Start**, **Analyze** or **Push**, the first one filled, and **Not now** puts a suggestion away until the situation changes. Next only gives the hint that starts something: once **Analyze** starts the Debugger on a failing check, its next moves (open the analysis, **Start fix**, **Push**) sit on that run's Activity row, and a workflow's ready step keeps its **Start** on the run row. Next does not repeat them. **Open a pull request** names the branch it opens in its title, as in **Open a pull request for hl/refund-retry**, with the project and the commits ahead under it. With several branches still without a pull request, Next shows one card for the branch furthest ahead, **⋯** lists every one of them, and **Not now** moves the card to the next branch. Once a pull request merges, Next offers **Remove the payments-api worktree** with the reason and its size (`#418 merged · 412 MB`), or one row for several merged worktrees. When the button starts an agent, the icon on the left is that agent's role in its color, and the button carries the same icon. Other ways to do it, such as starting a tester instead, sit in the **⋯** menu, where pointing at one shows its role on the icon. **Not now** says Dismissed with **Undo**, and ⌘Z brings the last dismissed suggestion back, several times in reverse order.

**Needs you** and **Next** group their rows by what you do, always in this order: **Decide** (a plan waits on your OK, a question), **Fix** (a stuck agent, a failing check, review conversations), **Update** (branches behind or diverged) and **Ship** (push, open a pull request, mark ready, merge, clean up). An empty group is not drawn. Each group folds behind its name with its row count and, while folded, the branches or plans it holds; the first group with rows opens, and what you open or fold stays as you left it for that session (`nextGroupsOf`, `NextGroup`, the `next-view` store slice). Inside a group the row that unblocks most comes first, such as a plan that covers 4 branches before a single retry, or a rebase of 8 branches before one push (`nextUnblockCountOf`). Rows that unblock as much keep the place they had when they first showed in this window, so a refresh never moves them and a new one lands after them. Each card counts its own rows in its header.

An item is in **Next** only while you are the next one to act. An agent Auto started that you stopped or declined leaves Next and shows in the full log as "You stopped the reviewer"; one a later agent replaced on the same branch leaves too. A stopped rebase of a branch that is still behind is not a card of its own: the "branches behind" card says how many rebases stopped and lists each one in its **⋯** menu.

Each branch, pull request or Auto plan shows once per kind of work. When an agent Auto started is stuck on a branch that also has a failing check, or two of its agents are stuck there, Next shows one row led by the worst blocker (blocked, then timed out, then never started, then a check), says "and 1 more" in its sentence and puts the others in its **⋯** menu. A stuck agent reads by its role and state, as in "The tester timed out. It ran out of time.", never the quoted request Auto sent it. A row's title is its subject: a plan that waits on your OK is titled by the plan's name, with the sentence "Plan v3 waits on your OK. The run covers 4 branches." (the branches its agents work on; `planSentenceOf`), and a **Fix** row on a known branch is titled by the branch and its open pull request, as in "hl/feat-center-home-page · #9995", with one sentence under it such as "4 review conversations wait for a fix." (`nextRowCopyOf`, `useBranchNames`). Rows in **Update** and **Ship** keep their verb titles, except a stopped rebase: it is titled by its branch, says in one sentence what stopped ("2 files conflict with main: MembersPage.tsx and 1 more. Your branch is as it was.", from `rebaseStopRowOf`) and leads with the verb that fixes it, **Resolve with Auto**, **Bring them in**, **Retry rebase** or **Fix with agent**, with **Resolve myself**, **Keep branch as it was**, **Undo rebase** and **Open branch** in its **⋯** menu as they apply; a click on its title opens the branch with the rebase panel. A diverged card of the same branch folds into that row and its verb into the **⋯** menu, never as "and 1 more" (`foldDivergedIntoStops` in `actionCardsOf`). Stopped rebases of other branches fold into the **⋯** menu of the Update card that counts them, each as a title ("Rebase of hl/feat-center-home-page stopped") with a short second line that wraps and clamps at three lines ("Conflict in SideBarFooter.tsx, PastDue.tsx and 3 more", "Origin moved"; `historyStopDetailOf`, `foldedVerbOf`), while the full sentence with the file paths stays in Needs you. That menu is at most 384px wide (`MENU_MAX_WIDTH`) and opens under its **⋯** button, aligned to its end, inside the window. When every open question out of view was asked by one Auto run (its root or an agent it started), **Answer open questions** is not a row of its own: it folds into that run's Decide row as "and 2 questions", and **Answer** sits in the row's **⋯** menu (`askingAutoRootOf`, the `rootAgentId` of the answer-questions suggestion). Questions from two runs, or from an agent outside Auto, keep their own row.

A group can act on its rows at once from its header (`nextBulkOf`). **Fix** with two or more stuck agents Auto can retry shows **Retry 3**, counting the stuck agents folded into a branch row too: it runs each agent's own **Retry**, so each one reports its own result, a row whose retry fails stays with its error and a second **Retry 3** runs again. **Update** with two or more branches behind or stopped shows **Update all 4** (`updateAll`): one click rebases every behind branch and every stopped one with git, one at a time, and brings origin in on each branch where someone pushed, each with its own lease. It never hands a conflict to Auto and never starts the History rewriter: a branch that stops on a conflict stays as its own row with **Resolve with Auto**, and a branch that fails keeps its row with the error, so its own verb retries it. A second click while it runs does nothing. The rebase picker with **Also tidy commits with Auto** stays on the rebase card itself. A click on a row's title opens its place: a stuck agent or a plan opens the Auto step, a check, review conversations or a pull request opens that tab of the branch, questions open the questions lens and an owner card opens its row (`openFor` in `useActionCardActions`, `suggestionPlaceOf`). A card that spans several branches, like the rebase card, opens nothing.

### Time left

See how long a step has left, estimated from your own past runs. Queued steps show a range, and a run slower than usual turns its time warm. Resting on the time opens a card with the time running, the usual range, the cost and the basis (`workTimeCardOf`).

### Changes

See and undo what agents changed in a session without a branch. In a plain folder agents edit in place, and every writing turn saves what it may change first, shell commands such as `rm` and `mv` and new files included. **Changes** in the session rail lists each turn, newest first, with the files it added, changed or removed and their line counts; pick a file to see its text before and after, with the changed words marked. **Restore to before turn 3** puts one file back, **Restore turn 3** puts back the whole turn, and **Remove this new file** takes out a file the agent created. Each restore first saves the text you have now, so **Undo restore** puts it back, and a restore over text that changed after the turn asks in place before it writes. The rail's **Folder** group names the folder and what agents do there, the Overview opens on a card that says where agents write and what is saved, and each writing turn in the chat ends in a card with **Review changes** and **Restore turn**. Versions are kept until 30 days after the session ends, within a cap per folder of 1 GB or the folder's own size, whichever is larger; the page shows how much they use, what was left out (files over 15 MB, links that leave the folder, dependencies and build output), and Storage shows their size under **Saved versions**. A session that still works in an older session folder keeps its list of file versions under the same page.
